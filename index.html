Lab procedure & reference

Use this simulator to observe scheduling behavior and verify the calculated metrics.

Aim

To simulate CPU scheduling policies and calculate each process's completion time, turnaround time, and waiting time from arrival and burst times.

Procedure

1. Add processes with non-negative arrival times and positive burst times.
2. Select a scheduling policy and set its quantum if needed.
3. Run the schedule; inspect the Gantt chart, operation log, and metrics.
4. Repeat with another policy to compare results.

Pseudocode

while unfinished processes remain:
    add arrived processes to the ready queue
    if the ready queue is empty:
        advance time to the next arrival
    else:
        select the next process by policy
        run it for its allowed CPU interval
        update remaining burst and time
        requeue it if it is not complete
for each process:
    turnaround = completion - arrival
    waiting = turnaround - burst

C code · FCFS example

#include <stdio.h>

int main(void) {
    int n, arrival[50], burst[50], completion[50];
    scanf("%d", &n);
    for (int i = 0; i < n; i++)
        scanf("%d %d", &arrival[i], &burst[i]);

    int time = 0;
    for (int i = 0; i < n; i++) {
        if (time < arrival[i]) time = arrival[i];
        time += burst[i];
        completion[i] = time;
        int turnaround = completion[i] - arrival[i];
        int waiting = turnaround - burst[i];
        printf("P%d: CT=%d TAT=%d WT=%d\n",
               i + 1, completion[i], turnaround, waiting);
    }
    return 0;
}

This compact example assumes processes are entered in arrival-time order; the simulator sorts arrivals and supports all four policies.

Frequently asked questions

What is the difference between turnaround and waiting time?

Turnaround is total time from arrival to completion. Waiting is time spent ready but not running, calculated here as turnaround minus CPU burst.

Why is there a gray block in my Gantt chart?

It represents CPU idle time: no process had arrived and become ready during that interval.

Is SJF preemptive? How does this MLFQ work?

SJF here is non-preemptive: once selected, a process runs to completion. The simplified MLFQ uses three round-robin queues with quanta 2, 4, and 8; new arrivals enter the highest-priority queue, and a process that uses a full slice without completing moves down one level. It does not interrupt an active slice for a newly arriving process.

Do the results persist when I close the page?

No. Everything runs locally in this page, and the workload is kept only in the current browser tab.
